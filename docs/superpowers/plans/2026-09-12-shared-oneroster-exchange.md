# Shared OneRoster Exchange Implementation Plan

Date: 2026-09-12
Status: Phase 2 conformance complete, Phase 3 scheduled exchange ready

## Goal

Build a complete, professional OneRoster implementation shared by ChurchCore Academy and ChurchCore LMS. OneRoster becomes the standard by which the two systems align and communicate.

## Non-Negotiables

- Academy remains the SIS and source of record.
- LMS remains independently usable in standalone mode.
- OneRoster is an exchange contract, not a replacement for either internal schema.
- No automatic Auth user provisioning without a later identity decision.
- No LMS-returned grade or progress can become an official Academy record without review.
- Secrets and passwords are excluded everywhere.

## Execution Order

1. Ratify OneRoster as the shared standard in Academy and LMS governance docs.
2. Add Academy's pure OneRoster CSV export contract and tests.
3. Add Academy repository-backed export from real academic-loop data.
4. Add Academy export route and admin preview/download workflow.
5. Add shared fixture package generated by Academy and consumed by LMS tests.
6. Harden LMS importer against the shared fixture.
7. Add scheduled transport and reconciliation.
8. Add OneRoster Gradebook Service style result return.
9. Add end-to-end browser and linked database verification.

## Phase 3 Prompt

Use the software factory to continue the shared OneRoster exchange implementation. Start from ADR 0069, Council Review XVI, and `docs/integrations/oneroster-shared-exchange.md`. Build scheduled Academy-to-LMS exchange using the tenant-level OneRoster package route and LMS import validator: package hashes, idempotency keys, retry/audit records, operator-visible reconciliation, and explicit no-provider/standalone behavior.
