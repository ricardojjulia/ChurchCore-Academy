# Write-Path Integrity Audit

Date: 2026-10-08
Scope: Academy operational writes on `main` through PR `#238`, plus the guardian preference closeout on this branch
Status: implementation and reset-backed verification complete; protected PR delivery pending

## Audit Outcome

The permanent E2E Postgres-error guard and static swallowed-error review now protect the suite from
the failure class found during the 2026-10-06 operator dry run: a route returning success after a
database error aborted its transaction. Attendance persistence and read-back shipped in PR `#232`;
the guard shipped in PR `#235`.

This closeout found one remaining allowlisted defect. Guardian attendance notifications queried a
nonexistent `academy_people.notification_preferences` column, and the guardian preference endpoint
returned success without writing anything. The preference is now stored on the specific
guardian/student relationship, read by the notifier, validated at the API boundary, and verified by
a browser/API journey that reads the persisted database value back. The temporary Postgres-error
allowance is removed.

## Residual Risk And Next Evidence

- The uncoached participant pilot remains deferred by owner decision; the local protocol is ready.
- Hosted deployment, live communications/payments, and Moodle/Canvas activation remain separately
  approved external gates.
- Two Postgres error classes are intentionally generated by the AI routing journey to prove
  append-only HQ history and HQ RLS rejection. The final run classified five occurrences across
  those two classes as expected and zero as unexpected. Any other Postgres `ERROR` fails the run.
- New write paths must add success/read-back, validation/rejection, and tenant/role tests sized to risk.
