# Shared OneRoster Exchange

Date: 2026-09-12
Status: Phase 2 conformance implemented; scheduled exchange next

ChurchCore Academy and ChurchCore LMS use OneRoster as their shared roster, enrollment, class, course, academic-session, and gradebook exchange standard.

## Boundary

- Academy is the SIS and system of record.
- LMS is the learning runtime and may operate standalone.
- OneRoster is the exchange contract between them.
- Ed-Fi, PESC, and CLR remain adjacent standards for data-hub, transcript, and credential exchange.

## Supported File Set

Phase 1 uses OneRoster 1.2 CSV package files:

- `manifest.csv`
- `orgs.csv`
- `users.csv`
- `roles.csv`
- `academicSessions.csv`
- `courses.csv`
- `classes.csv`
- `enrollments.csv`

Empty files are not emitted. The manifest declares empty file types as `absent`.

## Source Rules

- `sourcedId` values must be stable across exports.
- Cross-file references must be valid before export.
- CSV output must escape commas, quotes, and line breaks.
- Passwords, access tokens, refresh tokens, client secrets, webhook secrets, and raw provider payloads must never be emitted.
- User names and contact fields are PII and must be handled as roster data, not logs or AI prompt content.

## Direction

1. Academy exports a OneRoster package from persisted tenant data.
2. LMS validates and stages the package.
3. LMS preview reports create, update, unchanged, deactivate, and quarantine counts.
4. LMS apply mutates LMS-owned runtime records through service-only functions.
5. LMS writes provenance links and source hashes.
6. LMS returns grade/progress outcomes to Academy as reviewed imports.
7. Academy posts official records only through registrar-approved workflows.

## Current Implementation

- Academy: `src/modules/oneroster-contract` can build tested OneRoster CSV package contents.
- Academy: `src/modules/oneroster-contract` maps repository-backed tenant people, course catalog, academic calendar, and section registrations into OneRoster CSV packages.
- Academy: `src/modules/lms-roster-source/oneroster.ts` maps tenant-scoped section roster source data into the shared OneRoster dataset.
- Academy: `/api/academy/lms/sections/[sectionId]/oneroster-package` returns an authenticated institution-admin OneRoster CSV JSON package for a section.
- Academy: `/api/academy/lms/oneroster-package` returns the authenticated tenant-level ChurchCore OneRoster provider package as JSON preview data or `format=zip` download.
- Academy: `/admin/settings/lms` exposes OneRoster preview and ZIP download controls to institution administrators.
- Academy: `fixtures/oneroster/churchcore-academy-rostering-v1` is a deterministic package artifact generated by `npm run fixtures:oneroster`.
- Academy: `src/modules/oneroster-standard` defines the shared profile IDs, OneRoster version constants, service lanes, official CSV vocabulary, and privacy/idempotency checks.
- LMS: `src/lib/oneroster` validates, stages, previews, applies, guards provenance, and links identities for existing profiles.
- LMS: `src/lib/oneroster/academy-contract.test.ts` validates the generated Academy fixture, verifies hashes, and proves ZIP extraction parity.
